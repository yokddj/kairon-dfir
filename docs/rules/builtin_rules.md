# Builtin rules

## What these are in this platform

In Kairon DFIR there are two distinct concepts:

1. **Rules** stored or imported:
   - heuristic
   - sigma
   - yara

2. **Builtin detections**:
   - automatic signals generated by code from tags and severity of normalized events

This document focuses on current **builtin detections**.

## Default state

Builtin detections are **enabled by default** if the runtime setting:

```text
AUTO_CREATE_HEURISTIC_DETECTIONS = true
```

## How to disable them

### Disable all

Set the runtime setting:

```text
AUTO_CREATE_HEURISTIC_DETECTIONS = false
```

### Disable specific builtins

Edit:

```text
backend/app/rules/builtin_detection_overrides.yaml
```

Example:

```yaml
disabled_rules:
  - suspicious_command_line
  - rdp_activity
```

Then restart the backend and worker so the change takes effect.

## Detail of each builtin

### 1. Suspicious command line

- **Internal ID**: `suspicious_command_line`
- **Severity**: inherits `event.severity`
- **What it looks for**: any event already tagged as `suspicious_command`
- **Why it is relevant**: it usually captures PowerShell encoded, download cradles, LOLBins, or very aggressive commands
- **Evidence it uses**: mainly EVTX 4688 and 4104, although it is not limited to EVTX
- **Fields consulted**:
  - `tags`
  - `process.command_line`
  - `powershell.script_block_text`
  - `event.severity`
- **Match example**: `powershell.exe -enc ...`
- **Possible false positives**: legitimate administration, defensive scripting, or corporate automation
- **How to investigate it**: review the command line, user, host, parent process, and execution time

### 2. Service installation

- **Internal ID**: `service_installation`
- **Severity**: inherits `event.severity`
- **What it looks for**: service creation with persistence tags
- **Evidence it uses**: EVTX 4697 and 7045
- **Fields consulted**:
  - `tags`
  - `service.name`
  - `service.image_path`
- **Match example**: a new service pointing to `C:\\Users\\...\\AppData\\...`
- **Possible false positives**: legitimate installers, EDR agents, support tools
- **How to investigate it**: review image path, account, start type, and whether the binary exists

### 3. Scheduled task persistence

- **Internal ID**: `scheduled_task_persistence`
- **Severity**: inherits `event.severity`
- **What it looks for**: creation or modification of tasks with persistence tags
- **Evidence it uses**: EVTX 4698, 4702, TaskScheduler 106/140/141/200/201/129
- **Fields consulted**:
  - `task.name`
  - `task.command`
  - `task.arguments`
  - `tags`
- **Match example**: a task that runs `powershell.exe` from a user path
- **Possible false positives**: legitimate software or administration tasks
- **How to investigate it**: review the name, command, user, frequency, and XML content

### Additional Scheduled Tasks

- `scheduled_task_powershell_encoded`: tasks with `PowerShell` and `-EncodedCommand`
- `scheduled_task_runs_from_appdata`: actions pointing to `AppData`
- `scheduled_task_runs_from_temp`: actions pointing to `Temp`
- `scheduled_task_hidden_and_enabled`: `Hidden=true` and `Enabled=true` with suspicious traits
- `scheduled_task_lolbin`: use of `mshta`, `regsvr32`, `wscript`, `cscript`, `certutil`, `bitsadmin`, etc.
- `scheduled_task_unc_path`: action pointing to `\\host\share\...`
- `scheduled_task_com_handler`: observed `ComHandler` tasks
- `downloaded_file_persisted_as_scheduled_task`: correlation between a Browser download and a task's action

### Additional PowerShell

- `powershell_encoded_command`: use of `-EncodedCommand`
- `powershell_download_cradle`: download or cradle via `Invoke-WebRequest`, `DownloadString`, `WebClient`, or `Start-BitsTransfer`
- `powershell_invoke_expression`: `IEX` / `Invoke-Expression`
- `powershell_execution_policy_bypass`: `ExecutionPolicy Bypass`
- `powershell_defender_tampering`: dangerous Defender exclusions or changes
- `powershell_scheduled_task_persistence`: creation or registration of tasks
- `powershell_run_key_persistence`: persistence in Run Keys
- `powershell_credential_access_keywords`: references to `LSASS`, `mimikatz`, `sekurlsa`, `procdump`, `comsvcs.dll`
- `powershell_download_from_raw_ip`: direct URL to an IP
- `powershell_script_in_user_writable_path`: script observed in suspicious user paths

### Additional Recycle Bin

- `recycle_bin_executable_deleted`: executable sent to the recycle bin
- `recycle_bin_script_deleted`: script sent to the recycle bin
- `recycle_bin_deleted_download`: downloaded file that was later recycled
- `recycle_bin_deleted_defender_detection`: file detected by Defender and later recycled
- `recycle_bin_double_extension_deleted`: suspicious double extension recycled
- `recycle_bin_content_missing`: `$I` metadata present without `$R`
- `recycle_bin_suspicious_tool_deleted`: sensitive tool/payload recycled
- `recycle_bin_deleted_file_in_user_writable_path`: file recycled from Downloads, Desktop, Temp, AppData, Public, or ProgramData

### Additional Shellbags

- `shellbag_network_share_accessed`: UNC or share folder observed in Shellbags
- `shellbag_usb_folder_accessed`: folder on a removable/USB volume observed
- `shellbag_suspicious_tool_folder`: folder with names like `mimikatz`, `rclone`, `payload`, `credentials`, `dump`
- `shellbag_cloud_sync_folder`: OneDrive, Dropbox, Google Drive, Box, Mega, or Nextcloud folder
- `shellbag_user_writable_suspicious_path`: folder in AppData, Temp, Downloads, or similar with suspicious traits
- `shellbag_deleted_or_missing_folder_candidate`: Shellbag that appears to point to a deleted or missing folder
- `shellbag_folder_related_to_deleted_download`: Shellbag folder that correlates with a download later recycled or deleted

### Additional USB

- `usb_storage_device_observed`: USB storage device with useful serial/vendor/product or volume information
- `usb_executable_accessed`: executable or DLL observed on a removable path
- `usb_script_accessed`: script observed on a removable path
- `browser_download_to_usb`: direct download to an external drive
- `powershell_copy_to_usb`: copy/move/compression command toward USB
- `usb_suspicious_tool_observed`: sensitive tooling on removable storage
- `possible_usb_exfiltration_candidate`: hypothesis of data exfiltration to USB
- `deleted_file_from_usb`: file deleted or recycled from a removable drive
- `network_or_cloud_to_usb_correlation`: network/cloud activity related to USB activity
- `multiple_file_creations_on_usb`: burst of changes on the removable drive

### Additional WMI

- `wmi_persistence_chain_detected`: WMI chain of filter + consumer + binding
- `wmi_command_line_event_consumer_suspicious_command`: WMI consumer with PowerShell, LOLBins, or sensitive commands
- `wmi_active_script_event_consumer`: ActiveScriptEventConsumer with script
- `wmi_encoded_powershell_consumer`: PowerShell encoded inside the consumer
- `wmi_download_command`: WMI consumer that downloads remote content
- `wmi_registry_trigger`: WQL query based on `RegistryValueChangeEvent`
- `wmi_process_start_trigger`: WQL query based on `Win32_ProcessStartTrace` or similar events
- `wmi_consumer_references_user_writable_path`: consumer pointing to AppData, Temp, ProgramData, or Public
- `wmi_consumer_payload_executed`: WMI payload with execution correlation
- `wmi_consumer_payload_detected_by_defender`: WMI payload correlated with Defender

### Additional Autoruns / ASEP

- `autorun_from_user_writable_path`: ASEP entry pointing to AppData, Temp, ProgramData, or user paths
- `unsigned_autorun_in_persistence_location`: unsigned or unverified persistence
- `autorun_uses_lolbin`: ASEP using PowerShell, rundll32, regsvr32, mshta, wscript, or other LOLBins
- `autorun_encoded_powershell`: PowerShell encoded inside the ASEP
- `autorun_download_command`: ASEP that downloads remote content or references UNC paths
- `ifeo_debugger_persistence`: persistence via IFEO Debugger
- `winlogon_shell_userinit_modified`: modified Shell/Userinit
- `appinit_appcert_dll_persistence`: persistence via AppInit/AppCert DLLs
- `service_or_driver_from_user_writable_path`: service or driver outside standard paths
- `startup_folder_suspicious_executable`: suspicious executable or script in the Startup folder
- `autorun_target_detected_by_defender`: ASEP target correlated with Defender
- `autorun_target_executed`: ASEP target executed afterward
- `downloaded_then_persisted`: download -> persistence chain

### Additional Network / WLAN / DNS

- `hosts_file_redirects_security_domain`: `hosts` redirects a Microsoft, Defender, security, or critical vendor domain
- `suspicious_hosts_file_entry`: `hosts` override that deserves review even if not automatically high confidence
- `open_wifi_profile_observed`: WLAN profile with open authentication or no encryption
- `suspicious_dns_server_configuration`: unusual DNS configuration or one with risk signals
- `powershell_network_indicator_correlated_with_dns`: PowerShell URL, domain, or IP correlated with DNS or other network indicators
- `bits_domain_correlated_with_dns`: BITS domain also observed in DNS or related network activity
- `browser_domain_affected_by_hosts_override`: Browser accesses a domain affected by a local `hosts` override
- `direct_ip_network_connection_by_suspicious_process`: `netstat` connection to a direct IP with a suspicious process when the output allows it
- `cloud_provider_network_activity`: network activity related to observed cloud providers
- `wlan_connection_near_suspicious_activity`: WLAN connection or change close in time to other higher-risk activity

### 4. Possible exfiltration tool

### 4i. Registry Persistence via UNC Path

### 4k. Double Extension File

- **Internal ID**: `double_extension_file`
- **What it looks for**: names like `invoice.pdf.exe`
- **Evidence it uses**: MFT / USN
- **How to investigate it**: validate origin, user, path, and whether it was opened or executed

### 4l. Deleted Executable Candidate

- **Internal ID**: `deleted_executable_candidate`
- **What it looks for**: scripts or executables with `InUse = false`
- **Evidence it uses**: MFT
- **How to investigate it**: correlate with USN, Prefetch, EVTX 4688, and LNK/Jump Lists

### 4m. Executable in Downloads

- **Internal ID**: `executable_in_downloads`
- **What it looks for**: executables or scripts in suspicious user paths
- **Evidence it uses**: MFT / USN
- **How to investigate it**: review whether the file was executed, whether it has ADS, and whether it appears in the Registry or Defender

### 4n. Possible Timestomping SI/FN Mismatch

- **Internal ID**: `possible_timestomping_si_fn_mismatch`
- **What it looks for**: wide discrepancies between `$SI` and `$FN`
- **Evidence it uses**: MFT
- **How to investigate it**: compare timestamps, review the file's context, and do not treat it as conclusive proof on its own

### 5. RDP activity

- **Internal ID**: `rdp_activity`
- **What it looks for**: events with the `rdp` tag
- **Evidence it uses**: 4624 LogonType 10, 1149, 21/24/25, 4778/4779
- **Fields consulted**:
  - `tags`
  - `source.ip`
  - `user.name`
  - `windows.logon_type`
- **Match example**: successful RDP authentication from a remote IP
- **False positives**: remote support or legitimate administration
- **Investigation**: review source, time, user, and destination host

### 6. Lateral movement candidate

- **Internal ID**: `lateral_movement_candidate`
- **What it looks for**: `lateral_movement_candidate` tags
- **Evidence it uses**: remote events, services, authentication, or lateral tooling
- **Fields consulted**:
  - `tags`
  - `process.command_line`
  - `service.image_path`
  - `source.ip`
- **Investigation**: correlate with RDP, SMB, services, and credentials

### 7. High-risk event

- **Internal ID**: `high_risk_event`
- **What it looks for**: events with severity `high` or `critical`
- **Evidence it uses**: any
- **Fields consulted**:
  - `event.severity`
  - `event.type`
  - `event.message`
  - `tags`
- **How to investigate it**: open the event and review the reason for the severity

## Current limitations

- There is not yet a visual manager to disable builtins one by one.
- Individual disabling is done via a YAML file in the backend.
- Builtin logic depends on tags and severity already computed by parsers/normalizers.

## Execution artifacts

### Amcache Executable In Downloads

- **Internal ID**: `amcache_executable_in_downloads`
- **What it looks for**: executables or scripts observed by Amcache inside `Downloads`
- **How to investigate it**: review Browser downloads, hash, publisher, and whether `Prefetch` or `4688` also exists

### Amcache Executable In AppData

- **Internal ID**: `amcache_executable_in_appdata`
- **What it looks for**: binaries observed by Amcache in `AppData`, `Temp`, or other similar paths
- **How to investigate it**: validate it as presence/possible use and only elevate it with strong correlation

### ShimCache Suspicious Path

- **Internal ID**: `shimcache_suspicious_path`
- **What it looks for**: `ShimCache` / `AppCompat` entries in suspicious or UNC paths
- **How to investigate it**: do not present it as confirmed execution on its own

### AppCompat LOLBin Observed

- **Internal ID**: `appcompat_lolbin_observed`
- **What it looks for**: `powershell.exe`, `cmd.exe`, `rundll32.exe`, `certutil.exe`, and other LOLBins observed in compatibility artifacts
- **How to investigate it**: correlate with strong execution sources and user context

### Remote Access Tool Observed

- **Internal ID**: `remote_access_tool_observed`
- **What it looks for**: `AnyDesk`, `TeamViewer`, `ngrok`, `plink`, and similar tools observed in compatibility artifacts
- **How to investigate it**: validate whether the tool was authorized and whether associated remote activity occurred

### Double Extension Program Observed

- **Internal ID**: `double_extension_program_observed`
- **What it looks for**: binaries like `invoice.pdf.exe` or `photo.jpg.exe`
- **How to investigate it**: cross-reference with Browser downloads, `MFT/USN`, and strong execution

### Downloaded Program Observed In Amcache

- **Internal ID**: `downloaded_program_observed_in_amcache`
- **What it looks for**: a file downloaded by the browser that later appears observed in Amcache
- **How to investigate it**: confirm path, timing, and whether strong execution also exists

### Program Observed And Executed

- **Internal ID**: `program_observed_and_executed`
- **What it looks for**: Amcache/AppCompat correlated with `Prefetch` or `EVTX 4688`
- **How to investigate it**: review the exact pairing and the evidence -> observation -> execution chain

### Program Observed And Detected By Defender

- **Internal ID**: `program_observed_and_detected_by_defender`
- **What it looks for**: a program observed in Amcache/AppCompat that also appears in Defender
- **How to investigate it**: validate hash/path and the action taken by Defender

## SRUM rules

### SRUM High Upload

- **Internal ID**: `srum_high_upload`
- **What it looks for**: applications with a high upload volume in SRUM
- **How to investigate it**: review process, user, volume, and correlation with Browser, Prefetch, EVTX, and Defender

### SRUM Remote Access Tool Network Usage

- **Internal ID**: `srum_remote_access_tool_network_usage`
- **What it looks for**: `AnyDesk`, `TeamViewer`, `RustDesk`, and similar tools with network activity in SRUM
- **How to investigate it**: validate whether it was authorized remote support and correlate with strong execution

### SRUM File Transfer Tool Network Usage

- **Internal ID**: `srum_file_transfer_tool_network_usage`
- **What it looks for**: `rclone`, `WinSCP`, `FileZilla`, and similar utilities with SRUM traffic
- **How to investigate it**: review volume, timing, binary origin, and whether associated files existed

### SRUM LOLBin Network Usage

- **Internal ID**: `srum_lolbin_network_usage`
- **What it looks for**: `powershell.exe`, `bitsadmin.exe`, `certutil.exe`, `curl.exe`, etc. with network activity
- **How to investigate it**: correlate with `4688`, PowerShell, and downloads

### SRUM Suspicious Path Network Usage

- **Internal ID**: `srum_suspicious_path_network_usage`
- **What it looks for**: processes in AppData, Temp, Downloads, or other sensitive paths with network activity in SRUM
- **How to investigate it**: validate path, binary, and whether there is correlation with Browser, MFT, or Amcache

### SRUM Possible Exfiltration Candidate

- **Internal ID**: `srum_possible_exfiltration_candidate`
- **What it looks for**: high upload or an unbalanced upload/download ratio
- **How to investigate it**: keep wording cautious and review context, volume, application, and other sources

### SRUM Browser Download Correlation

- **Internal ID**: `srum_browser_download_correlation`
- **What it looks for**: a program downloaded from the browser that later appears active in SRUM
- **How to investigate it**: review the download domain, timing, and whether additional execution occurred

### SRUM Downloaded Program Network Active

- **Internal ID**: `srum_downloaded_program_network_active`
- **What it looks for**: a downloaded program that also had network activity and, sometimes, strong execution
- **How to investigate it**: review the download -> observation -> execution -> network chain
